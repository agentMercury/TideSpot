## 三、发现的偏差与风险（验收关注项）

### 偏差 ①：Top10 会混入历史窗口（中，功能正确性）
- **现象**：`BestWindowFinder.find` 签名没有 `nowEpochSec` 参数，候选集只按 `total>=60 && !雷暴` 过滤。其两个调用方都喂入**含过去 7 天**的分数序列：
  - 详情页：`Derivations.buildScoreInputs`（Derivations.kt:186）对**全部** `slices`（含 `past_days=7`）算分 → `DetailStateHolder.onResult`（line 45）`top10(scores, …)` 直接传入。
  - 收藏读侧：`TideSpotRepository.topWindows`（line 388）把库内**全部** `hourly_score` 行（含过去）重建后传入。
- **后果**：若现在是 17:00，今早 6:00 出现 92 分窗口，该窗口会出现在"未来最佳窗口 Top10"里——违背 §6.6"从当前小时的下一整点起 N 天"的语义。
- **修复建议**：给 `find` 增 `nowEpochSec` 参数，候选集加 `timeEpochSec >= nowEpochSec`；详情与读侧都传入。该改动同步影响 `TopWindowDerivations.top10` 与 `topWindows`，需在 M6 一并改并补 `WindowFinderTest`（构造含过去小时的序列断言被剔除）。

### 偏差 ②：现场校潮"只算不应用、不持久化"（中，功能闭环缺口）
- **现状**：`DetailScreen.CalibrationSheetContent`（line 292-329）只调用 `manualFit` 并在文案里显示"已启用：滞后 Xh"，**没有把 lag 应用到 `sea_level_height_msl` 序列**（即校正后的潮高曲线 / dh/dt 副轴不会重算）。同时观测仅存于 `DetailViewModel._manualObservations`（Session 级），退出即丢，未落 `manual_observation` 表（schema 决策 HANDOVER 登记归 M6）。
- **后果**：用户走完现场校潮流程后，看不到任何"校正后"的潮位/潮流变化，功能价值未兑现；且每次重进都要重新记。
- **修复建议**：M6 落 `manual_observation` 表 + 接通"应用校正"（校正层已具备 `TideCalibrator.apply`，但需把 `ManualTideFit` 的 lag 适配成 `apply` 的输入）；潮 Tab（D12 待办）展示校正前后对照。若 M6 时间紧，至少应把观测与拟合参数持久化，并标注"下次刷新生效"。

### 偏差 ③：收藏列表跨时区时间错位（低-中，体验正确性）
- `FavoritesSummaryFormatter` / `FavoritesScreen` 用 `ZoneId.systemDefault()` 渲染摘要与 Top10 时刻，但收藏点可能在国外（如大阪 JST）。F-3.8 要求小时轴按"选点当地墙上时间"，详情页已做（注入 `spot.tzOffsetSec`），列表侧未做。
- **建议**：`FavoriteSpot` 携带 `tzOffsetSec`（或从 spot 表 join），列表/Top10 用 `ZoneOffset.ofTotalSeconds(tz)` 渲染。

### 偏差 ④：雷暴判定用中文子串（低，i18n 隐患）
- `BestWindowFinder.hasThunderstorm`（line 122）用 `vetoReasons.any { it.contains("雷暴") }`。M6 已有 FO-01"雷暴判定用结构化机器码，禁中文子串 `contains("雷暴")`"——此处是 M5 输出与 M6 规范的衔接缝。
- **建议**：`vetoReasons` 改为结构化标记（如枚举 `VetoReason.THUNDERSTORM`），或至少用机器码常量；同步影响 `warningsOf`（D09 待办中的"ΠV 逐项乘子 + 月龄/照明/中天"也应结构化）。

### 偏差 ⑤：水质 Tab 徽标硬编码（低）
- `DetailScreen`（line 196-199）直接 `ConfidenceBadge(Kind.ESTIMATED)` 硬编码，与 M6 D10"按 Confidence 动态接线，禁硬编码 ESTIMATED"冲突；属 M5 输出与 M6 收尾的交接缝。

### 偏差 ⑥：F-2.5 相对时间（低）
- 规格示例为 `明日 17:00 · 92 分 · 爆护窗口`，实现用 `11月6日 17:00`。绝对时间无误但不够"钓鱼友好"，建议 v1.1 改相对日期（今天/明天/周X）。

### 挂起项（非 M5 缺陷，记录备查）
- 新建收藏坐标为占位 0.0/0.0，真实"准星收藏"主路径需 M6 接线。
- 跨点 Top10 跳过潮汐去重（保真损失，见 F-2.6 备注）。
- F-2.3 详情页导航接线（M6）。

## 四、改进意见（APP 完工后的 v1.1 优化需求池）

> 以下条目作为 v1.1 候选优化需求。标注【M6 顺手修】的应优先在 M6 收尾时一并处理，因为它们是 M5 输出与既有规范的衔接缝，成本极低。

### OPT-M5-01｜Top10 增加"未来窗口"硬过滤 + 读侧保真潮汐去重【M6 顺手修】
- **背景**：偏差 ①。§6.6 明确要求"从当前下一整点起"。
- **建议**：`find` 增 `nowEpochSec`，双调用方传入；读侧 `topWindows` 若要做海钓点去重，需在 `hourly_score` 落库时附带 dh（或在读侧用 `marine` 现算 dh，但读侧无 marine——建议改为存 `sea_level_height_msl` 于 `hourly_metric` 或在 `hourly_score` 增 `dhM` 列）。
- **优先级**：高（正确性）。**涉及**：`BestWindowFinder`、`TopWindowDerivations`、`TideSpotRepository`、`WindowFinderTest`。

### OPT-M5-02｜现场校潮消费侧闭环（应用校正 + 持久化）【M6 顺手修 / 留 v1.1】
- **背景**：偏差 ②。
- **建议**：观测落 `manual_observation` 表；提供"应用"入口把 `ManualTideFit.lag` 喂给 `TideCalibrator.apply` 重算潮位/潮流；潮 Tab 展示校正前/后潮高曲线与 dh/dt 副轴（接 D12）。
- **优先级**：高（功能价值）。**涉及**：`TideCalibrator`、`DetailViewModel`、`DetailScreen`、Room schema（M6）。

### OPT-M5-03｜收藏列表/Top10 按选点时区渲染【M6 顺手修】
- **背景**：偏差 ③。
- **建议**：`FavoriteSpot` 增加 `tzOffsetSec`（或为 domain 模型补该字段，CONTRACT 只增不改）；`FavoritesSummaryFormatter` / `Top10Content` 用 `ZoneOffset.ofTotalSeconds(tz)`。
- **优先级**：中。**涉及**：`Models.kt`、`FavoritesSummaryFormatter`、`FavoritesScreen`。

### OPT-M5-04｜vetoReasons 结构化 + 雷暴机器码判定【M6 顺手修】
- **背景**：偏差 ④ + D09。
- **建议**：`FishScoreResult.vetoReasons` 由 `List<String>` 文本改为 `List<VetoReason>` 枚举/结构化；`hasThunderstorm`、`warningsOf`、FactorBreakdown 的 ΠV 明细统一消费结构化标记，消除对中文文案的依赖，为 i18n（英）铺路。
- **优先级**：中（i18n 前置）。**涉及**：`VetoEvaluator`、`FishScoreCalculator`、`BestWindowFinder`、`Derivations`。

### OPT-M5-05｜ConfidenceBadge 动态接线，去除硬编码 ESTIMATED【M6 顺手修】
- **背景**：偏差 ⑤ + D10。
- **建议**：水质 Tab 的水温/DO/浊度/叶绿素各值带各自 `Confidence`，徽标逐值动态渲染（实测/卫星/模型/估算），而非整 Tab 写死"估算"。
- **优先级**：低-中。**涉及**：`DetailScreen`、`ConfidenceBadge`、`WaterQualityProxy`。

### OPT-M5-06｜F-2.5 相对时间格式（今天/明天/周X）
- **背景**：偏差 ⑥。
- **建议**：`FavoritesSummaryFormatter` 增加相对日期模式（同一天内 → "今天 HH:mm"；次日 → "明天 HH:mm"；其余 → "周X HH:mm / M月d日 HH:mm"）。
- **优先级**：低。**涉及**：`FavoritesSummaryFormatter`。

### OPT-M5-07｜地图准星一键收藏（打通主路径）
- **背景**：F-2.1 主路径当前未接线（坐标占位）。
- **建议**：M6 `:app` 组装时，地图长按/确认准星 → 弹出收藏对话框，预填逆地理名称 + 携带 `lat/lon/waterBody/elevation/tzOffsetSec`；编辑时 D07 patch 已能保证不冲掉这些派生列。
- **优先级**：高（核心路径）。**涉及**：`:app` 导航、MapScreen、FavoritesViewModel。

### OPT-M5-08｜现场校潮支持"涨/退潮时刻"两类观测 + 时刻可改
- **背景**：规格 §6.2b 规则 5 允许记录"涨/退潮时刻"或"高低潮时刻"，当前 UI 仅"记录一条高潮观测"（取 `System.currentTimeMillis()`）。
- **建议**：① 允许用户在记录时标注"高潮/低潮/我看到的涨潮/退潮"；② 允许手动选择观测时刻（事后补记）；③ 展示模型极值时刻对照，辅助用户对齐。
- **优先级**：中。**涉及**：`DetailScreen`、`TideCalibrator`（极端值匹配可扩展为涨/落段匹配）。

### OPT-M5-09｜水质实测值录入入口（manual_observation 的 UI 落地）
- **背景**：SRS §5.3 明确"保留手动录入实测值入口（`manual_observation`，参与 §6.1.3 校准）"，但本次走查未发现对应 UI。
- **建议**：水质 Tab 增加"录入实测（水温/DO/浊度）"入口，落 `manual_observation` 并触发 §6.1.3 的 `0.6·实测 + 0.4·模型` 融合 + 徽标改"实测+模型"。
- **优先级**：中（提升近岸/养殖点可用性）。**涉及**：`DetailScreen`、`:core:data`、`WaterTemp`。

### OPT-M5-10｜跨点 Top10 性能与缓存
- **背景**：`FavoritesViewModel.load` 每次进收藏列表对每点调 `topWindows`（无网 DB 读 + 现算 find）。收藏点多时无缓存，频繁重算。
- **建议**：将各点 Top10 结果缓存（内存 + 可选落库），仅在数据刷新/排序切换时按需更新；或读侧直接落 `best_window` 表（含 rank），避免每次重建 + find。
- **优先级**：低（100 条内当前可接受）。**涉及**：`FavoritesViewModel`、`TideSpotRepository`。

### OPT-M5-11｜"出发时间"感知的窗口推荐（智能筛选）
- **背景**：当前 Top10 是"未来 7/10 天全局价值排序"，但用户常问"我周六下午有空，哪段最好"。
- **建议**：v1.1 增加"指定日期/时段筛选 Top10"或"临近 X 小时内窗口优先"视图，复用现有 `find` 输出。
- **优先级**：低（体验加分）。**涉及**：`BestWindowFinder`、`DetailScreen`/`FavoritesScreen`。

### OPT-M5-12｜Top10 注意事项增强（校正状态提示）
- **背景**：若启用潮位校正（偏差 ② 闭环后），Top10 注意事项应提示"已按现场校正滞后 Xh"，让用户知道窗口时刻已校正。
- **建议**：`warningsOf` 在存在有效 `ManualTideFit`/`Calibration` 时追加校正说明。
- **优先级**：低。**涉及**：`BestWindowFinder`、`TopWindowDerivations`。
