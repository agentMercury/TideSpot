## 3. 必须闭环的缺陷清单（M4 开工前 / M6 组装时）

### P0（阻断 F-1.6 与 M4 数据流）

**NEW-01 · 水体判定在整条产品链路上不存在（上轮 GAP-M3-02 低估）**
实测：`classify()` 调用点全仓检索**只出现在单测**；`onSpotConfirmed(GeoPoint, NamedPlace?)` 不携带类型；`spot.waterBodyType` 没有任何生产写入（FavoriteSpot 默认 LAND）；MapScreen 无收藏入口（§8.1 信息条应含 [确定][收藏]）。
→ 后果：M4 的 Tab 标题联动、评分预设选择拿不到判定结果；「判定与 §6.9 一致并缓存」这条退出标准整句不成立。
→ 闭环：确认选点流水线补「marineAllNull+elevation → classify() → 随回调下传并写 spot 表」；`SpotDao` 增一个 `updateWaterBody(id,type,elevation)` 级别的最小写入口。

**NEW-02 · elevation 数据断流：判定与库表都是死列**
实测：`WeatherResponseDto.elevation` 有值 → `repo/` 目录 grep elevation **零引用** → `SpotEntity.elevation`/`tzOffsetSec` 两列无任何写入路径；单测 `elevation透出供水体判定_收藏水体类型持久化`（RepositoryTest:369）**名不副实**：只断言了 waterBodyType 透传，elevation 仅断言 DTO 层。
→ 后果：即使 NEW-01 接好，classify() 也拿不到 elevation；跨时区收藏点无 tzOffsetSec 可用（F-3.8 依赖）。
→ 闭环：refreshSpotDetail 时把 weather dto 的 elevation/utc_offset_seconds 回写 spot 表，并**把该单测改成真断言**。

### P1（M4 开工前修完，成本合计 ≤2 天）

**NEW-03 · §6.9 判定树私自加捷径 + 无 UNKNOWN + 探针故障期误判固化 30 天**
`decide()` 中 `elevation ≤ 3m → INLAND_WATER 且跳过探针` 是 SRS 没有的规则（低海拔陆地点误判成湖）；OSTIA 探针 null（**当前图层实测 500**，A6-r4）时千岛湖 (elev 99) → **LAND 并缓存 30 天**，与掩膜确认无值的 LAND 不可区分；`WaterBodyType` 无 UNKNOWN，§6.9 第 4 级「未知+徽标」不可表达；`probe=null`（M6 忘注入凭据时默认）静默全 LAND，无告警。
→ 闭环：删捷径或改 `≤3m 仍探针`；枚举增 UNKNOWN（只增不改合规）；**探针失败结果用短 TTL（24h）入库**；probe 缺注入时 log.warn。

**NEW-04 · 逆地理降级/节流结果钉 30 天（继承上轮 GAP-M3-06，维持 P1）**
RG-A/RG-B 失败或被 `tryAcquire` 丢弃时无条件 upsert RG-D + 30d TTL，`ReverseGeocoderTest:246` 已把缺陷固化为预期；「连续确认两点」第二点必丢地名 30 天。令牌桶语义应改等待（可取消），UI 显示「正在解析地名」。

**NEW-05 · F-1.4 拖动重对准路径不通 + 相机动画中间帧污染 center**
`onMapMoved` 仅 Preview 生效 → 已确认后拖动永远等不到「移动中，点确定切换」；`animateCamera` 每帧回调覆写 center，全仓 **无一处 onCameraIdle 门控**（实测 grep 零命中），长按后立刻点「确定」提交的是**动画中间帧坐标**（错点选水域是实害）；单测 `confirmed_movedAndConfirm_doNotSwitchData` 把缺陷钉成预期。修复时**必须同步改这两条断言**，否则绿灯继续撒谎。

**NEW-06 · utc_offset_seconds 缺失按 0 处理（M2 遗留，影响面大）**
`Mappers.kt:98/129/162/204` `dto.utcOffsetSeconds ?: 0` ——源缺偏移时按 UTC+0 解析当地墙串，**hourEpoch 整体平移**，TTL/窗口/跨日界/收藏点比较全错。这正是 §5.0「null 禁止当 0」禁止的同型问题。闭环：缺 offset 时回退 `ZoneId.of(dto.timezoneId)` 或显式标错降级，禁默默 0。

**NEW-07 · 定位路径断链（继承 GAP-M3-04）+ 冷启动权限往返**
`locateMe()` 只 animateCamera 不设准星（§13 五路径之一断）；冷启动不查 `checkSelfPermission` 已授权态就发权限请求（轻）。

### P2（M6 组装时一并闭环）

**NEW-R1 · MIGRATION_1_2 无任何注册点**：全仓零 `databaseBuilder/addMigrations`（M6 忘写 = 升级用户 IllegalStateException）；RoomDaoTest/RoomMigrationTest 两个 @Ignore 留真机。建议 M6 前引入 **Robolectric** 在 JVM 里先吃掉这两块（见 OPT-32），别全押真机。

## 7. 结论

M1/M2/M3 的**单元层质量是扎实的、可信的**；但 M3 按 SRS §11 口径**尚不满足退出标准**——水体判定与选点确认链路在集成层面不存在（NEW-01/02），两条 F-1.4/F-1.6 验收场景在真实交互中不可触发（NEW-03/05）。与前轮结论不同处，本报告全部给出一手反证（字节码、30 万点对照、全仓调用点检索），三条纠正：MapView 崩溃风险降级、OLC 归责反转、classify 接线缺失升级。风险集中在「接线层零测试覆盖 + 缺陷被断言固化」这一结构性盲区：修缺陷的同时必须修测试断言，并尽快按 OPT-28/32 建 CI 与 Robolectric 兜底。
