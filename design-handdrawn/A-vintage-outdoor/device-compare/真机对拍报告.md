**此前把早期 base 旧稿标成"设计稿"与真机并排、称"对齐/通过"，属参照错位，在此更正。** 这不是某一张图做坏了，而是本目录的对照曾把两个并存版本当成同一张稿的"设计 vs 实现"。

## 1. 第一轮结论（修复前 · 历史留档）

**部分通过，不建议直接铺开到全 App。**

局部主题这条链路是通的：详情页背景、Tab 栏底、标题衬线字族、深色背景都按 A 版 token 真实生效，地图/收藏两页保持原蓝色未受影响，说明「只换一屏」的边界正确。

但真机暴露出**工程既存的硬编码色**：分数主卡、日历选中态、图表/卡片底不读 `MaterialTheme`，浅色与深色下颜色完全一样，在米黄纸底和深墨绿底上都显得突兀。这是试点最有价值的发现——**光靠一层主题覆盖不足以完成整屏换皮**。

另外，对照图里"看起来完全不一样"的**主因**是参照了两套并存的稿（见 §0 勘误：旧 base 稿 vs 真机参照的新稿），并非单纯"手绘未工程化"；手绘语言（纸纹、鱼形、套印、手绘地图、鱼群档位）未工程化只是**叠加**其上的次要差距，属已知试点边界，不是回归。

## 4. 根因（精确到代码行）

| 现象 | 代码位置 | 原因 |

## 5. 与"设计稿"的整体差距（已知边界，非回归）

**先纠正归因**：此前的并排图左列是**早期 base 旧稿**（78/白底/潮流图），右列真机参照的是**新稿**（82/苔绿/绿柱）——两列本就不是同一张稿，结构、分数、卡片形态、图表类型全不同（详见 §0 勘误）。所以"差距"里最大的一块来自**参照错位**，不能算作"实现得不够像"。

在此前提下，真机相对新稿仍缺的手绘语言包括：做旧纸纹、套印错位、非对称圆角、鱼形装饰（前三项已由 D5 的 `HandDrawn.kt` + drawable 近似工程化）、手绘地图带（确认不做）、五档鱼数中的鱼形细节。图表仍是工程既有 `HourChart` 的 Canvas 柱状/折线，手绘笔触是固定 seed 的抖动近似，不是 SVG path 的 1:1 搬运。

这是 `Compose试点落地说明.md` 写明的边界：**结构层从不是像素级复刻，只做配色 token + 局部装饰近似**。不承诺 1:1。

## 12. V4 · ① 阶段：五档鱼数 / Tab 鱼图标 / 图表手绘笔触（2026-11-12 15:5x）

### 12.1 范围决策（含一次显式确认）

① 原指「补手绘地图 / 图表笔触 / 五档色带鱼数图标」。探查后发现三项风险差异极大：

- 设计稿详情页的「手绘地图」是**静态 SVG 装饰带**（`engine.py:395-437`），
  上面写着「⌖ 拖动地图选点」；但工程详情页**不能选点**（选点在地图页），
  原样搬过去会造出一个点不动的假功能入口，正好踩红线。
- 工程地图页用 **CARTO 真实矢量瓦片**（`MapScreen.kt` 的 MapLibre style URL），
  不是静态底图，无法 1:1 变成手绘；要改只能叠滤镜，会把试点从一屏扩到两屏。

因此就「手绘地图做到哪一档」显式询问用户，用户选择 **「本轮不做地图带」**：
只补五档鱼数、图表笔触、Tab 鱼图标与布局对齐，地图带留到全 App 铺开阶段。
**地图页本轮零改动，试点仍是一屏。**

### 12.2 改了什么（3 个文件，纯视觉）

| 文件 | 改动 |
