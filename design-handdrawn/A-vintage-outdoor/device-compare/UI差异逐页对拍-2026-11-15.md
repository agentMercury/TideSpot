> ⚠️ **历史快照（2026-11-15）**｜§5 的 S2/S3 排期结论已被 **CHG-95** 取代（S2b 只做收藏/详情且**设置页不动**、**S3 放弃**）；§1–§4 的差异与成因分析仍然有效，勿把旧排期当现状。

> 对象：`screens/` + `screens_full/`（30 屏设计稿） vs `device-compare/` 真机截图（AAK-AN00 / 1272×2800 / A 皮肤）
> 工程基线：v1.19.0（`593757f`，全屏换肤已落地）；真机截图取 r2（换肤对拍）/ r5（四选与 Top10）/ v4（详情页试点）

## 0. 结论速览

差异**不是同一个原因**，分三类，必须分开处理，否则会做无用功：

1. **主动取舍（占视觉差异最大一块）**：2026-11-13 客户确认的验收口径是「配色 token 层 + 功能入口红线，**不追结构/布局 1:1**」。工程因此只换了颜色 token、纸纹与少量装饰，页面骨架仍是既有 Material 3 组件。设计稿里的双线票据卡、虚线分隔、鱼形图标、票据式信息条、衬线大标题全部**没有进入实现范围**，这不是回归。
2. **迁移损耗 / 实现缺陷（可修，收益最高）**：纸纹 tile 用低频正余弦 + 高对比墨色颗粒，导致真机底色变灰变暗、出现规则网格；`FontFamily.Serif` 在 Android 对中文回落到无衬线 CJK，设计稿的楷体/衬线气质整体丢失；`handDrawnOutline` / `printMisregister` 只在详情页 3 处调用，其余 3 页完全没有描边与套印。
3. **参照稿问题（必须先解决，否则越修越偏）**：`screens/detail-sea.png` / `detail-inland.png` 是早期 base 旧稿（78 分 / 白底 / 潮高·潮流折线），真机参照的是 `screens_full/detail-tab-score-*`（82 分 / 苔绿 / 钓鱼指数柱）。历史对照曾把两版混挂并称「对齐」，见 `真机对拍报告.md` §0 勘误。另外 30 屏里**没有深色设置页稿、没有深色 Top10 叠层稿**，深色只能靠 token 推断。

**一句话**：要最大限度接近设计图，先定稿 + 修质感/字体（低风险、高收益），再谈结构层；结构层是否跟进需要客户重新授权。

## 2. 量化基线（纯色区采样，可复核）

用 Pillow 取「本应纯色」的区域，统计 RGB 中位数、灰度标准差、颜色种类数。设计稿 780×1688、真机 760×1672，按相对坐标取样。

| 区域 | 设计稿 | 真机 | 判读 |
|---|---|---|---|
| 设置页左侧纸底 | `#DFD4B8`，std 1.42，14 色 | `#D3CBB4`，std 4.12，77 色 | 真机偏暗偏灰、颗粒可见 |
| 收藏页下部背景（浅） | `#D6C9A8`，std 1.53，122 色 | `#D3CBB4`，std **11.26**，1487 色 | **灰度方差 7.4 倍**、颜色数 12 倍 → 规则网格纸纹 |
| 收藏页下部背景（深） | `#122334`，std 0.59，28 色 | `#202A36`，std **9.75**，818 色 | 真机亮 14 级、失去藏蓝倾向，方差 16 倍 |

对应 `r2-换肤对拍.md` §4 的实测：浅色页面底 token `#E4D9BC` → 真机 `#D0C8B0`（约 −8%），深色内陆 `#101D18` → `#202A24`。

**成因定位**：`gen_android_assets.py:grain_tile()` 用 `TILE=96` 的 96px 周期低频正弦/余弦斑驳（`0.24·sin(2πx/T)cos(2πy/T)+…`）混合白噪，`drawable-nodpi` 不随密度缩放 → 在 560dpi 屏上形成肉眼可见的规则网格；颗粒色 `INK_LIGHT=(28,34,27)` 墨绿 / `INK_DARK=(247,241,222)` 暖白，与纸底**高对比**，`HandDrawn.kt:paperGrain()` 又以 `drawContent(); drawRect(brush, alpha=strength)` 把整层盖在**所有内容之上**（含卡片与文字），于是整体被压暗、压灰、去饱和。设计稿的 `feTurbulence fractalNoise baseFrequency=0.82`（`engine.py:paper.base_freq`）是高频细噪，与纸底同色系，几乎不改变底色。

## 5. 解决方案（按「投入 / 收益 / 风险」分层）

### S0 · 先定稿（不写代码，但决定后面所有事）

1. **指定唯一权威稿**：详情页以 `screens_full/detail-tab-score-{sea,inland}.png` 为准；`screens/detail-*.png` 加「历史旧稿·非落地目标」标记并**从对照矩阵移除**（`make_pairs.py` 已把它单列为勘误组）。
2. **修稿内不一致**：SCORE Tab 的图表类型（折线潮高 vs 钓鱼指数柱）二选一，重渲该屏 + 更新 `spec.json` SHA + `index-full.html`。
3. **补缺稿**：深色设置页、深色 Top10 叠层、至少 4 个状态态的深色版本；否则深色只能靠推断。
4. **冻结一份「视觉 token 表」**：把 `engine.py:STYLES['a-vintage']['pal']` 的 `bg / card / card2 / line / ink / muted / accent` 与 `radius / font / grain` 导出为 `spec.json` 的一个 `visual_tokens` 节点，工程侧 `TideSpotSkin.kt` 逐项对齐，`SkinRegistryTest` 加断言防漂移。

### S1 · 低风险高收益（建议先做，不改结构、不动功能）

| 项 | 改动 | 验收 |
|---|---|---|
| 纸纹重做 | `gen_android_assets.py:grain_tile()` 去掉 96px 低频正弦项，改高频分形白噪（周期 ≤ 8px、幅度 ≤ 0.05），颗粒色改**纸底同色系 ±5%**；`A` 的 `grainStrength` 由 `1f` 降到 `0.45~0.6`（D 皮肤已用 `0.45f`） | 纯色区灰度 std ≤ 设计稿 ×2；底色 RGB 中位差 ≤ 8/通道（现值浅色 −12、深色 +14） |
| 字族 | 引入一款可商用中文衬线字体（思源宋体 / 霞鹜文楷等）子集，放 `core/ui/src/main/res/font/`；`VintageTypography` 改 `FontFamily(Font(R.font.xxx))`，数字槽位单独 `Georgia 系`；补 `letterSpacing` | 中文标题目视有衬线；换行位置不回归（字号/行高**禁止改**，见 `TideSpotSkin.kt:288` 注释）；D 皮肤字族不受影响 |

### S2 · 结构层对齐（需客户重新授权，中等风险）

- 设置页：把裸列表改回 6 张分组卡片 + 虚线行 + 小鱼标题；控件从 FilterChip 换成设计稿的下拉/文本值形态（**注意**：这会改变交互方式，需逐项确认可用性）。
- 收藏页：卡片改紧凑票据式（圆形选择圈 + 大号分数 + 档位 + 小鱼），补页头与副标题；Top10 横幅内嵌鱼形序列。
- 详情页：主卡补 `/100`、实测/模型圆徽标、虚线鱼框；Tab 栏改整条描边容器 + 选中下划线；图表按 S0 定稿结果统一类型并加强手绘笔触。
- 地图页：把「全部收藏 Top10」横幅改回**双线白纸信息卡**（含地名/水体徽标/分数/鱼框/Top10 行），保留真实瓦片。

风险：改布局会触发全页回归（多分辨率、字体缩放、TalkBack）、可能触碰冻结契约的 `DaySelector 52dp` / 水质 1×3；必须沿用 `check_entries_v4.py` 的关键元素 bounds 校验方式，**每次改动前后跑 36 项入口红线**。

### S3 · 地图底图（需产品决策，收益与代价都大）

三条路，按「接近度」递增：
1. **保持真实瓦片**，只把浮层/信息卡风格化（S2 范围），最稳，但底图永远不像设计稿。
2. **自定义 MapLibre style JSON**：用 `map_land / map_water / map_road` 三色重写图层、隐藏 POI 与路名、路网改成米白曲线 → 视觉上接近手绘插画，**仍是可拖动真实地图**。这是「最大限度接近」且不牺牲功能的最优解，需新增一份本地/远程 style（URL 必须走 `TideSpotUrls.kt` 单点）。
3. **静态手绘地图带**：已裁决不做，且带误导文案，不推荐。

### S4 · 验收：把「接近」变成可度量的门禁

1. `make_pairs.py` 纳入常规验收：每次换肤/改皮肤后重跑，生成并排图并人工逐页签字。
2. 自动量化：纯色区 RGB 中位差、灰度 std、颜色种类数三项阈值（S1 已给），写进 `.tools/` 脚本。
3. 结构：沿用 `check_entries_v4.py` 的「关键元素 bounds 与可交互节点数」比对，改布局前后必须零回归。
4. 三轴正交回归：皮肤 × 水体 × 明暗四态截图矩阵（v4 已有 8 张）必须补齐并复拍。
5. 门禁：八模块单测 / `i18n_scan` FAIL=0 / `contrast_check` FAIL=0 / `assembleRelease`；发版按 §0.6 升版本号。

### S5 · 经验同步（问题真正解决后再做）

按客户要求，把本次结论写进 `SKIN-DEV-STANDARD.md`（版本号 +1 + 顶部变更行）与 `SKIN-DESIGN-SPEC.md`：
- 「设计稿版本选择」红线：新旧稿不得混挂，对照矩阵必须写进脚本；
- 「设计源 → 工程」的四个高频损耗点：SVG filter ≠ 程序化噪点、系统 serif ≠ 中文衬线、CSS 描边/阴影 ≠ M3 Card、静态示例数据 ≠ 业务数据；
- 「token 对齐 ≠ 视觉对齐」：质感叠加层会改变底色，必须量化纯色区；
- 「深色稿缺失」：新增皮肤必须交付完整深浅 × 双水体矩阵，否则深色只能推断；
