# 潮点 TideSpot · 皮肤（Skin）设计规范

> 配套需求：**OPT-A-09**（提供换皮肤 / UI 样式切换功能）｜ 明暗开关：**OPT-A-03**（独立正交轴）
> 版本：1.0 ｜ 日期：2026-11-12 ｜ 设计基线：手绘 A · 复古户外（本轮唯一内置皮肤）
> 性质：**设计与工程共用契约**——定义「什么算一套皮肤」「哪些能换、哪些绝不能换」「以后怎么加一套皮肤」。不含 Compose 实现代码、不改工程源码。

---

## 0. 一句话原则

**皮肤 = 一组可替换的「视觉 token」，不是一套重新画的页面。** 结构、文案、交互、状态、Tab 序全部共用一套；换肤只把 token 表整组替换，全屏一致生效。任何需要「改布局 / 改文案 / 改逻辑」的都不是换肤，应另立需求。

**首版只内置 1 款皮肤：手绘 A「复古户外」。** B/C/D 是独立风格探索稿，**不作为皮肤、不并入、不做成可选项**；选择页其余槽位一律标「即将推出 / 敬请期待」占位。

---

## 1. 三轴正交（最关键的心智模型）

换肤最容易出错的地方，是把「风格 / 水体 / 明暗」三个维度混为一谈。本规范强制三轴正交：

| 轴 | 取值 | 谁决定 | 换它时不动谁 |
|---|---|---|---|
| **皮肤 Skin** | A 复古户外（首版仅此一款；未来可加） | 用户偏好，设置页「外观 · 皮肤」选 | 不动水体、不动明暗；冻结契约逐项不变 |
| **水体 Water** | 海洋/近海 ↔ 内陆/湖泊 | **当前点位数据**决定，用户不可切 | 任何皮肤下都必须保留「双水体六重区分」 |
| **明暗 Mode** | 跟随系统 / 浅 / 深（OPT-A-03） | 用户偏好 + 系统 | 不动皮肤、不动水体；切明暗不重置皮肤 |

**组合规则**：`最终视觉 = 皮肤token(水体) × 明暗模式`。即每款皮肤须为**海洋/内陆各备一套色板**，明暗再在两套之上派生深色 token。三轴各自独立持久化，任一轴切换不重置另外两轴。

> ⚠️ 反例（禁止）：把 A 的冷蓝/暖绿两套水体配色当成「两款皮肤」让用户切——那会破坏「配色区分水体」的语义，切完就分不清海/陆了。水体配色差异是**语义**，不是**风格**。

## 2. 皮肤 token 清单（可变 vs 冻结）

### 2.2 冻结，绝不进皮肤 token（换肤前后逐项回归）

1. **Tab 渲染序**：钓鱼指数 → 潮流(水位) → 天气 → 水质 → 风浪
2. **免责 5 条原文**（工程 D11「现场校潮」长文为准）
3. **五档分数色 = `ScoreBands.kt`、六徽标色 = `ConfidenceBadge.kt`**（冻结语义单源；档位恒带文字 N-7，不得只靠颜色）
4. **DaySelector 两行 52dp**；**水质 1 行 × 3 卡**（水温/溶解氧/浊度，pH 已删，不随皮肤增删卡）
5. **地图优先、无底部 NavigationBar**；**准星唯一选点真源 F-1.3**
6. **双水体六重区分方式**：徽标 / 配色冷暖 / 鱼种 / 第二 Tab / 图表单位 / 地点——换肤只改**配色明度与装饰画风**，六重的**区分关系**必须保留（海仍冷、陆仍暖；海鱼≠淡水鱼；潮流≠水位）
7. **全部文案**：取 `TideSpotStrings.kt` 单源，不因换肤改写
8. **示例数据**：分数/时刻/点位为版式示意、非业务数据，源更新时间显示「—」
9. **状态语义等级**：离线/陈旧/48h/分维降级四态的**语义与优先级**不变；仅允许其**表现色**随皮肤 token 派生（仍须满足对比度 ≥4.5:1）

> 判定口诀：**换「长什么样」✅；换「是什么 / 有几个 / 叫什么 / 排第几」❌。**

## 4. 工程接入契约（供实现方）

1. **数据类**：`TideSpotSkin(id, name, nameEn, palettes{sea,inland}, fonts, shapes, texture, motifs, darkTokens)`；A 为 `TideSpotSkin.VintageOutdoor`。
2. **注册表**：`TideSpotSkins.all = [VintageOutdoor]`（首版仅一），`default = VintageOutdoor`；注册表是「未来加皮肤」的**唯一扩展点**。
3. **注入**：`TideSpotTheme(darkTheme, skin, water)` 由 `skin.palettes[water]` 派生 `ColorScheme` / `TideSpotShapes` / `TideSpotTypography`；**五档/六徽标色绕过皮肤，直取冻结单源**。
4. **持久化**：`skinId` 与 `themeMode` 分字段存，互不覆盖；冷启动分别回放。
5. **全屏一致**：所有 Composable 只从 `MaterialTheme.colorScheme` / `LocalSkin` 取色，禁止硬编码色值，否则换肤会漏屏（验收第 2 条）。
6. **水体联动**：皮肤色板须实现 `palettes[sea]` 与 `palettes[inland]` 两套，运行时按点位水体选取，不由用户切（第 1 节三轴正交）。

## 6. 验收清单（换肤功能上线前必过）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 入口可达 | 设置页「外观·皮肤」进选择页，显示当前皮肤 = A 复古户外 |
| 2 | 全屏一致 | 换肤后逐屏走查（详情/地图/收藏/设置/深色/各叠层/状态态），无单屏漏切、无硬编码色残留 |
| 3 | 首版唯一 | 只有 A 一款可选，其余为「敬请期待」占位、不可误点 |
| 4 | 冻结契约 | §2.2 的 1–9 逐项回归通过；五档/六徽标语义色未变 |
| 5 | 双水体可辨 | 换肤后海洋/内陆仍一眼可辨（六重区分保持） |
| 6 | 三轴正交 | 切皮肤不重置明暗/水体，切明暗不重置皮肤，各自持久化 |
| 7 | 对比度 | 冻结语义色与状态色在浅/深下均 ≥4.5:1 |
| 8 | 可扩展 | 照 §5 清单加一套测试皮肤，业务 Composable 零改动即可生效 |
